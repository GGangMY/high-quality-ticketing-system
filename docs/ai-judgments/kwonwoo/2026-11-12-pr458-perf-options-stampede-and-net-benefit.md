# 좌석 조회·갱신 통합(1-1)에서 사전 배치 캐시 참조를 거부하고 손익 검증 뒤 적용 대상을 추림

## 맥락
- 해결하려던 작업: PR #458(`feat/ISE-79-seat-hold-race-condition`)과 측정 브랜치(`experiment/ISE-79-k6-steps`)에서 기본 부하(K1 L) 100% 통과 이후, 심화 측정(Z·K·X·4코어 상한)에서 드러난 성능 지표를 더 끌어올릴 후속 개선안을 도출하려 했다.
- AI 활용 방식: PR #458과 측정 브랜치 코드 기준으로 지표를 더 끌어올릴 방안과 트레이드오프를 물은 뒤, AI가 1-1(`UPDATE ... RETURNING` 통합)의 전제로 제안한 "사전 소속 검사를 캐시된 배치로 대체"에 대해 캐시 스탬피드(Cache Stampede) 문제 가능성을 지적했다. 이어서 모든 방안의 구체적인 단점·해결 방안·실제 손익(이득 vs 손실)을 다시 검증하게 했다.

## AI 제안
1. 1차 제안: 선점 경로(1-1~1-6), 좌석 조회 경로(2-1~2-3), 만료 스케줄러(3-1~3-3), 인프라·Gateway·DB 설정(4-1~4-3) 등 총 15개 개선안 제시. 그중 1-1은 `findSeats`(SELECT)와 `holdAvailableSeats`(UPDATE)를 `UPDATE ... RETURNING` 한 문장으로 합치되, `400 SEAT_COUNT_MISMATCH`와 `409 SEAT_ALREADY_HELD`를 구분하기 위해 P4b 배치 캐시를 참조하는 안을 포함했다.
2. 사용자 지적 후 2차·3차 검증([학습 노트](../../learning/kwonwoo/qna/2026-11-12-pr458-further-performance-improvements.md)):
   - 1-1에서 트랜잭션 내부가 배치 캐시(`SharedLoadCache`)를 기다리면 캐시 미스 순간 선점 스레드가 DB 커넥션을 쥔 채 대기하고 캐시 로더는 커넥션을 얻지 못하는 **커넥션 풀 교착(Starvation Deadlock)**이 날 수 있음을 확인했다. 캐시 없이 `UPDATE ... RETURNING` 후 실패 시에만 `COUNT`를 조회하는 대안도 409 비율이 77%인 K1에서는 왕복 절감 실익이 작아(0.5ms 미만) 보류로 판정했다.
   - 15개 방안을 손익 기준으로 재판정해, 외부 계약·정합성 위험이 큰 항목(409 충돌 좌석 ID 반환, Redis 사전 거절, 매수 Upsert + Sequence 배치, 상태 비트맵 분리, 묶음 만료)은 기각하고, 이득이 확실한 항목(만료 상한 1,000 확대, 만료 시 `releaseQuota → releaseSeats` 2줄 순서 변경, 선점 세마포어로 조회 커넥션 보호, `nanoTime` 경과 시간 검사로 유령 선점 차단, 공유 설정 R1·P1, P4b~P4d 협업, Gateway 차단기·동시 상한 세트)만 채택 대상으로 추렸다.

## 판단
- 결과: 부분 수용 (1-1의 사전 배치 캐시 참조 거부, 손익 검증으로 추린 핵심 개선안 수용 및 다른 에이전트 작업에 반영 지시)
- 판단자: KWON-WOO
- 근거: 1-1에서 배치 캐시를 참조하면 캐시 스탬피드 상황에서 문제가 생길 여지가 있다고 판단해 지적했고, 각 방안의 구체적인 단점·해결책·손익 비교 결과를 다른 에이전트에서 진행 중인 추가 작업에 포함시키기로 했다.
- 검토한 대안:
  - 1-1 사전 배치 캐시 참조 vs 캐시 없이 `UPDATE ... RETURNING` 후 실패 시에만 `SELECT COUNT(*)` 사후 판별 vs 현행 유지(선점 단독 K1-H 800명 p99 6ms라 현행 유지가 복잡도 대비 유리)
  - 잠긴 행 번짐 방어: Redis 사전 거절(캐시 해제 누락 시 영구 판매 불가 위험) vs `SyncSeatHoldService` 진입 세마포어(정합성 위험 없이 좌석 조회 커넥션 보장)
  - 만료 적체 해소: 50건 묶음(Chunk) 만료(추첨 연장 분기 복잡화·다중 행 데드락 위험) vs 단건 만료 유지 + 배치 상한 `100 → 1,000` 확대 및 `releaseQuota → releaseSeats` 잠금 순서 정렬

## 발표·면접 포인트
- AI가 제안한 "DB 조회를 줄이기 위해 선점 트랜잭션에서 배치 캐시를 참조하자"는 안에 대해, 캐시 미스(스탬피드) 순간 트랜잭션이 DB 커넥션을 쥔 채 캐시 로딩을 기다리면 **커넥션 풀 교착(Starvation Deadlock)**이 발생한다는 점을 짚어내어 거부했다.
- 모든 성능 개선 후보를 무조건 넣지 않고, "K1에서 409가 77%라는 실측 분포"와 "좌석 정합성(유령 매진 0)"을 기준으로 손익을 따져 Redis 사전 거절·묶음 만료 같은 고위험 안을 쳐내고 세마포어·경과 시간 검사·만료 상한 확대 같은 저위험 고효율 안만 추렸다.
