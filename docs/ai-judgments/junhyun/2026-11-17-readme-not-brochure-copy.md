# README를 브로셔 내용으로 꾸미자는 AI 안을 거부하고, 프로젝트를 드러내는 README를 따로 쓰기로 함

## 맥락
- 해결하려던 작업: 저장소 README를 다이어그램과 그림을 써서 보기 좋게 고치는 일(ISE-308).
- AI 활용 방식: "리드미를 이쁘게, 다이어그램과 그림을 적절히" 요청했다.

## AI 제안
ISE-299에서 브로셔를 바탕으로 쓴 README의 내용을 그대로 두고 겉모양만 바꾸는 안. 배포 서버 접속 배지, 브로셔의 숫자 카드와 성능 차트, Mermaid 다이어그램 8개를 더했다.

## 판단
- 결과: 거부
- 판단자: 안준현
- 근거: 브로셔와 똑같이 만들 필요가 없고, 프로젝트를 잘 나타내는 README를 따로 써 달라는 요청이었다. 배포 서버는 이번 주까지만 운영하고 내리므로 이를 감안해야 한다.
- 검토한 대안: 없음

## 반영
README를 "어떤 문제를 어떻게 풀었고 무엇으로 확인했는지" 중심으로 새로 썼다. 배포 서버 주소에 기대는 링크를 빼고, 화면 캡처와 로컬 실행 방법으로 대신했다(ISE-308, `README.md`).

## 검증
GitHub 브랜치 화면에서 Mermaid 렌더링을 확인했다.

## 판단 이력
- 2026-11-17 거부: 브로셔 내용을 꾸미는 안 대신 README를 따로 쓴다.

## 발표·면접 포인트
- 같은 사실이라도 독자에 따라 글을 다시 쓴다. 발표회 브로셔는 심사자용이고, README는 배포 서버가 내려간 뒤 저장소를 처음 여는 사람이 읽는다.
