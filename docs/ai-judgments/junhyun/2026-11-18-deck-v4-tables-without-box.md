# 발표 덱 v4 표를 상자 안에서 다듬은 AI 작업을 거부하고 상자를 없앤 뒤 표 자체를 다시 디자인함

## 맥락
- 해결하려던 작업: 발표 덱 v4에서 유리 상자 안에 넣어 둔 표 11개(결과보고서 장, 남은 과제, 부록)가 기본 회색 격자로 그려져 슬라이드 디자인과 어울리지 않았다.
- 요청: "박스안에 표 넣어놓은 거 다시 그려줘! 슬라이드 디자인에 어울리게 다시 그리되, 너무 요란하지는 않게."

## AI 제안
- Claude Code는 "상자 안의 표"를 다시 그리라는 뜻으로 읽고, 상자는 그대로 둔 채 표의 격자만 머리줄 굵은 선과 줄 사이 점선으로 바꾸고 있었다.

## 판단
- 결과: 거부
- 판단자: 안준현
- 근거: "박스안에 표 형식을 유지하는게 아니라, 박스를 없애고 표를 다시 디자인하라는 말이었어!"

## 반영
- 표를 감싼 유리 상자를 모두 걷었다. 상자 안에 표와 함께 있던 칩과 설명 문장은 표 위아래에 그대로 두었다.
- 표 자체를 덱 문법에 맞춰 다시 그렸다. 위아래 3px 잉크 선, 머리줄 아래 3px 선, 줄 사이는 목차·병목 지도와 같은 점선, 세로줄 없음, 빛 덩어리 위에서도 읽히도록 옅은 흰 바탕을 깔았다.
- 첫 칸은 굵게, 결과 칸은 파랑, 피드백 상태(반영·변경·대체·부분)는 작은 표식으로 바꾸고 예외만 노랑으로 했다. API 표의 메서드·경로는 코드 글꼴, 부록 A1의 64 줄은 옅은 노랑으로 표시했다.
- 규칙은 `deck.css` 한 곳에 두어 표 11개에 같이 적용했다.

## 검증
- 표가 있는 11장을 Chrome headless로 그려 넘침·겹침 검사를 통과했고, 그림으로 눈으로 확인한 뒤 v4(버전 12)에 게시했다.

## 판단 이력
- 2026-11-18 거부: 상자 유지안 대신 상자를 없애고 표를 다시 디자인

## 발표·면접 포인트
- "상자 안의 표"처럼 대상과 범위가 겹쳐 읽히는 요청은 무엇을 바꾸는지(상자인지 표인지) 먼저 확인해야 했다.
