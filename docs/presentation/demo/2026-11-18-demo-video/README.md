# 서비스 소개 겸 시연 영상

발표와 결과 제출에 쓰는 소개 겸 시연 영상이다. 완성본은 [`../2026-11-18-demo-video.mp4`](../2026-11-18-demo-video.mp4)(2분 26초, 1920×1080, 30fps)이다. 앞부분에서 문제와 해법을 소개하고, 가운데에서 실제 화면으로 일반 예매(토스페이먼츠 결제창, 결제사 응답 지연 뒤 확정), 추첨 응모·당첨·자동결제, AI 예매 상담, 발권 기념 부적을 보여 주고, 끝에서 화면 뒤의 구조와 숫자를 보여 준다.

같은 날 먼저 만든 48초짜리 일반 예매 시연(판 1)을 사용자가 보고 "토스페이먼츠 연결과 이것저것 더, 소개와 시연을 같이, 추첨 응모·당첨도"를 요청해 다시 기획했다. 세 기획안은 [`STORYLINES.md`](STORYLINES.md)에 있다.

## 사용자가 정한 것

- 기획 A "하린의 예매 하루"(소개 영상 v2의 세계를 잇는 문제 → 이선좌 → 실제 화면 시연 → 화면 뒤 숫자).
- 토스페이먼츠는 결제창만 보여 준다. 테스트 모드여도 카드사 인증(휴대폰·생년월일)이 필요해서, 결제 완료는 시연용 결제로 이어 가고 그 사실을 화면에 적는다.
- 더 보여 줄 기능: AI 예매 상담, 결제 실패 뒤 복구.
- 내레이션을 넣는다. 하린 대사는 소개 영상 v2 녹음을 다시 쓴다.
- 장면 10 내레이션은 사용자가 쓴 문장 "예매를 마치면 나만의 부적도 받을 수 있습니다. 접속해서 예매를 완료하고, 부적 하나씩 받아가세요!"를 그대로 쓴다.

## 콘티와 달라진 것(실제 동작에 맞춤)

- 장면 7: 콘티의 "결제사 연결이 원활하지 않습니다 → 다시 결제"는 승인 서킷 브레이커가 열려야 나오는 화면이다. 최근 승인 20건 중 절반 넘게 실패해야 열려서 한 번의 녹화로 만들기 어렵다. 그래서 같은 "결제 실패 뒤 복구"를 실제로 보여 주는 결제사 응답 지연 장면으로 바꿨다. Mock PG에 다음 승인 한 건 4초 지연을 걸면 결제 서비스가 2초에 결과를 모름으로 두고 "결제를 확인하는 중입니다"를 띄우고, 재확인이 승인을 찾아 예매를 확정한다. 내레이션도 "결제사 응답이 늦어도 걱정하지 마세요. 결제 결과를 다시 확인해 예매를 확정합니다."로 바꿨다.
- 장면 9: 예매 상담은 공연 정보가 아니라 예매 규정 문서를 찾아 답한다("예매 규정을 바탕으로 답변합니다"). "ASTERIA 공연은 몇 매까지?"는 규정에 없어 답하지 못해서, 질문을 "추첨에 당첨되면 결제는 어떻게 되나요?"로, 내레이션을 "예매 규정을 찾아 근거와 함께 답합니다"로 바꿨다.
- 장면 1의 하린 대사는 v2 녹음 "이번엔 절대 못 놓쳐!"를 쓴다(콘티 초안 "이번엔 꼭 잡는다!" 대신, 사용자 요청: 재활용 가능한 대사는 재활용).

## 사실 확인

- 시연 화면은 모두 실제 동작이다. 2026-11-18 로컬 스택을 최신 dev(`0160192f`)로 다시 빌드하고, 배포 서버와 같은 시드(`seed-showcase.sh`, `seed-demo.sh`)를 넣은 뒤 샘플 계정으로 찍었다. 결제 서비스는 `PAYMENT_PG_PROVIDER=toss`, `PAYMENT_PG_MOCK_BYPASS=true`로, Mock PG는 장애 주입이 열리는 `loadtest` 프로필로 띄웠다.
- 토스페이먼츠 결제창은 실제 테스트 결제창(`payment-gateway-sandbox.tosspayments.com`, "실제 결제가 안되는 테스트입니다")이다. 카드 인증은 하지 않고 닫았고, 이어지는 결제는 "토스연동 건너뛰고 결제하기"(Mock PG)다.
- 추첨은 `seed-demo.sh lottery`로 응모 3분, 추첨 1분 뒤인 추첨을 만들었다. 이 시드는 공연 이름을 "k6 측정 추첨"으로 만들어서, 로컬 DB에서만 그 회차(50)를 대표 공연(ASTERIA)으로 옮기고 임시 공연(34)을 숨겼다. 자동결제 카드는 시연용 Mock 빌링이다. 응모자가 혼자라 바로 당첨됐다.
- 잘라 낸 곳: 시연 1 오픈 대기 약 25초, 시연 2 재확인 대기 약 15초, 시연 3 응모 시작 대기 약 18초와 추첨·자동결제 대기 약 4분. 자른 자리마다 "잠시 뒤", "응모 시작", "추첨 시각"으로 표시했다.
- 화면 뒤 숫자는 발표 덱 값이다. 2만 2천 명 대기·순번 확인 p95 11.7ms(11/17 실측 1회), 좌석의 8배가 몰린 매진에서 1,500석 중 1,498석 판매·중복 판매 0(11/17), 동시 처리 제한 64로 p95 571→87ms(11/11). 내레이션의 "대부분 0.02초 안에"는 p95 11.7ms를 말로 옮긴 것이다.
- 깔끔한 화면을 위해 로컬 DB에서만 예전 확인용 공연 9개와 리허설 회차 4개를 숨겼다. 배포 서버와 저장소 코드는 바꾸지 않았다.

## 다시 렌더하기(이 폴더에서)

```bash
mkdir -p assets/fonts assets/sfx
cp ../../../../frontend/node_modules/pretendard/dist/web/variable/woff2/PretendardVariable.woff2 assets/fonts/
for i in "soft mouse click" "fast whoosh transition" "pop notification" "riser into impact"; do npx hyperframes media-use resolve --type sfx --intent "$i" --project . --local-only; done
cp .media/audio/sfx/*.mp3 assets/sfx/
python3 tools/build.py
npx hyperframes check && npx hyperframes render -q delivery -o renders/demo.mp4
ffmpeg -i renders/demo.mp4 -c:v copy -af loudnorm=I=-16:TP=-2.5:LRA=11 -c:a aac -b:a 192k -ar 48000 ../2026-11-18-demo-video.mp4
```

효과음 파일 이름(`sfx_001`~`sfx_004`)은 위 순서로 받았을 때의 이름이다. 다시 녹화하면 시각이 달라지므로 `tools/build.py`의 녹화 구간과 `tools/marks-*.json`을 새 녹화에 맞춘다. 녹화 스크립트는 프론트엔드 `node_modules`가 보이는 곳에서 실행한다(예: 실행 폴더에 `node_modules`를 연결).
