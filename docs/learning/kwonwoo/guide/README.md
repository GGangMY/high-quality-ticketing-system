# 이선좌 티켓팅 시스템 종합 학습자료

콘서트 티켓 오픈 순간의 폭주를 견디는 예매 서버를 처음 보는 사람이 한 번에 이해하도록 묶은 자료다. 2026-11-18 `dev`(병합 커밋 `7fef096a`)의 코드와 문서를 기준으로 썼다. "구현됨", "코드만 있고 운영에서 끔", "설계만"을 구분해 적었으니 발표나 면접에서 셋을 섞지 않는다.

## 한 문장 요약

> 놀이공원 인기 놀이기구 앞에 번호표 줄(대기열)을 세우고, 차례가 온 사람에게만 탑승권(입장 토큰)을 주고, 자리를 잠깐 맡아 둔 뒤(선점) 매표소(결제)에서 돈을 내면 표를 확정해 주는 시스템이다. 매표소 기계가 멈추거나 직원이 쪽지를 잃어버려도 돈과 좌석이 어긋나지 않게 하는 장치를 겹겹이 두고, 그 장치 하나하나를 측정으로 골랐다.

## 비유 사전

문서 전체에서 같은 비유를 쓴다.

| 시스템 요소 | 비유 |
|---|---|
| nginx + Gateway | 건물 정문과 1층 보안 데스크. 출입증(JWT)을 보고 어느 층으로 갈지 안내하고, 로비가 꽉 차면 입장을 잠시 막는다(상한 64) |
| Eureka | 사내 전화번호부. 서비스가 지금 어느 주소에 있는지 알려 준다 |
| Config Server | 본사 공지 게시판. 모든 지점이 같은 설정을 여기서 읽는다 |
| 대기열(Redis) | 놀이공원 번호표 발급기와 전광판 |
| 입장 토큰 | 차례가 된 사람에게 주는 10분짜리 탑승권. 자리를 잡으면 회수한다 |
| 좌석 선점(HELD) | 식당 자리에 가방을 올려 두는 것. 5분 안에 주문(결제)하지 않으면 치운다 |
| 잠금 대기 50ms | 화장실 앞에서 50ms만 기다리고 포기하기. 오래 기다리면 뒤 줄 전체가 멈춘다 |
| 결제 토큰 | 매표소에 내미는 "이 자리 맡은 사람 맞음" 확인증. 예매 창구만 도장을 찍을 수 있다(ES256) |
| PG | 카드사와 연결된 외부 매표 대행사 |
| Kafka | 부서 간 사내 우편함. 보낸 쪽은 넣고 끝, 받는 쪽은 자기 속도로 꺼내 본다 |
| Outbox | 우편물을 바로 부치지 않고 먼저 장부에 적어 두는 발송 대장 |
| Inbox(processed_events) | 받은 우편 접수 대장. 같은 편지가 두 번 와도 한 번만 처리한다 |
| DLQ | 반송함. 처리 못 한 우편을 버리지 않고 따로 모은다 |
| 서킷 브레이커 | 누전 차단기. 계속 실패하면 잠시 전기를 끊어 불이 번지지 않게 한다 |
| 대사(Reconciliation) | 가게 마감 정산. 장부와 금고를 맞춰 보고 다른 곳을 찾는다 |
| Jenkins + GHCR | 시설 관리자와 부품 창고. 새 부품이 다 오면 교체하고, 점검에 실패하면 이전 부품으로 되돌린다 |

## 면접 포인트 (전체)

- "티켓 오픈 폭주를 어떻게 견뎠나" → 대기열로 좌석 서비스에 들어오는 속도를 고정하고, 좌석 경합의 최종 판정은 DB 조건부 UPDATE에 맡겼다. 그 앞에 먼저 거절과 잠금 대기 50ms를 두어 지는 요청이 커넥션을 오래 쥐지 않게 했다. 분산락은 DB 제약과 이중이 되어 쓰지 않았다.
- "결제가 타임아웃 나면" → 실패가 아니라 "결과 모름(UNKNOWN)"으로 두고 202를 준 뒤 재확인 스케줄러가 PG에 다시 묻는다. 좌석은 그동안 잡아 둔다.
- "부하 테스트로 무엇을 개선했나" → 좌석 조회가 GC → 커넥션 대기 → DB 조인 → 직렬화 순서로 막혔고, 하나씩 고쳐 local 성공률 0.13%→100%, 배포 서버에서 실패 없이 버틴 좌석 조회 초당 5건→200건이 됐다. Gateway는 동시 처리 상한 64 등으로 같은 장비의 성공 처리량을 1,608에서 2,122/s로 올렸다.
- "측정이 예상과 달랐던 적은" → local에서 효과가 컸던 선점 동시 처리 상한이 배포에서는 503만 늘려 운영에서 껐다. local은 DB CPU가 넉넉해 운영 조건을 재현하지 못한다.
